# 实验方案与启动门槛

## 当前可以做什么

可以开始“环境与语义校准”：编译官方样例、确认具体API和输出参数、验证一对拷贝/别名行为。正式报告中的准确率、消融增益和真机残留率，应等下面P0门槛通过后再采集。

当前项目已存在 F1–F8、64个变体工程目录、B0/B1/B2及结果文件；这说明建设进度，不能单独证明样例可运行或标签独立正确。此次只读快照中的 `dynamic/heap_experiment/heap_results.json` 自报 Node.js v24.20.0/V8、10轮、`gcExposed:false`，字符串命中10/10、buffer路径命中0/10。这里只转述现有文件，未重跑或确认观测器无污染；不能写成ArkTS真机结果。项目仍在变化，后续应以冻结提交复核。

## RQ与实验设计

| 研究问题 | 输入 | 对照/消融 | 主要输出 |
|---|---|---|---|
| RQ1 能否正确区分句柄与材料、编码与包装？ | K01–K17及独立外部移植例 | B0/B1/B2；去掉表示类型/KEK恢复规则 | TP/FP/FN/TN；逐类别错误清单 |
| RQ2 跨语言建模是否必要？ | CrossFlowBench与K18–K26 | ArkTS-only；将Native当黑盒；手工摘要与自动摘要分开 | 边恢复率、最终风险判定、未解析调用比例 |
| RQ3 身份/字段/上下文敏感带来什么？ | K15–K17、K34–K40；按族隔离变体 | 去身份、去字段、去上下文，各自固定其余因素 | 配对通过率、ΔP/ΔR/ΔF1与耗时 |
| RQ4 对真实项目有用吗？ | 固定来源的候选项目，先做纳入筛选 | 相同可分析范围的基线 | 告警人工复核、独立风险数、分析覆盖、失败原因 |
| RQ5 清零/表示选择的动态现象可重复吗？ | 真机/模拟器中可编译的最小A/B工程 | 基线、正控、负控；新进程重复 | 可观测命中率、错误率、采集范围及限制 |

移植外部案例应保留原文件hash与转换diff。开发集和留出集按“来源/案例族”划分；同模板改变量名的A/B变体不能拆到训练与测试两边后当作独立泛化能力。若没有训练过程，也应区分规则开发时已见样例与规则冻结后的外部样例。

## Ground truth 规范

每个案例至少保存：`case_id/source_ref/source_commit/sdk/api/device/threat_model/secret_identity/entrypoint/path_condition/expected_recoverability/expected_policy_risk/expected_flow/expected_zeroized_regions/oracle/label_author/review_status`。CSV模板在 [examples](examples/ground-truth-template.csv)。

预期分类建议采用 `recoverable / not_recoverable_under_assumptions / possible / not_applicable / unknown`。另用独立字段记录“不可控字符串副本”“持久化策略违例”“日志暴露”“清零不充分”等风险。没有精确恢复不等于没有策略风险；公钥和IV也不应变成秘密阳性。

人工复核要依据API语义及可行执行路径；至少对争议和高价值案例做第二次独立复核。若只有一位标注者，如实写明，不虚构双人一致率。

## 统计与失败处理

- 在明确定义的二分类子集上计算 P=TP/(TP+FP)、R=TP/(TP+FN)、F1=2PR/(P+R)、FPR=FP/(FP+TN)。分母为0记NA，不能当0或100%。
- 同时报告覆盖率、Unknown、解析失败、超时和未支持API。不要把失败样例静默删除或计为安全负例。
- 报告每族结果和总体结果；一个源头的多条路径/重复告警按预先规定的单位去重。配对通过率要求 A/B 都判对，不能只看危险侧命中。
- 64个模板变体不是64个完全独立真实应用。置信区间或重采样按案例族/项目分组；阈值选择必须在留出评估前冻结。
- 记录冷/热启动、构建开销是否包含、超时限制、内存峰值；时间至少报告中位数与P95，运行重复次数和机器配置完整。

## 动态与清零实验协议

1. 固定设备、系统build、SDK/NDK、编译器、优化/LTO、应用类型和快照工具版本。HarmonyOS、OpenHarmony、Node/V8三种环境分别列出。
2. 控制进程生成/保存真值或经独立通道获取真值；目标进程不保留用于搜索的额外hex字符串。不能用只存在于 risky分支的人为marker制造不对称。
3. 每轮新进程、新秘密；采集操作前基线、操作后、释放/清零后快照。保留确认能找到受控活跃字节的正控；如果工具根本不覆盖Native区域，记not observable。
4. 搜索raw、hex、Base64等预先规定形式，并验证命中来源。记录是否真实触发GC、GC条件、截断、采集失败。缺失快照不能当阴性。
5. 先做5轮pilot确认机制，再预注册正式轮数（例如30轮，每轮独立，不是规范规定）。报告命中数/有效轮数及不确定性，不据0次命中断言绝无残留。
6. 清零另核对有效存储区域、范围和时序；反汇编检查最终链接产物而非仅查`.o`字符串；必要时用运行时观察交叉验证。
