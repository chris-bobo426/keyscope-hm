## 收集范围

覆盖 ArkTS/C++ 跨语言分析、密钥身份与表示、包装恢复条件、N-API 拷贝/别名、清零、密码误用基准、HarmonyOS 运行观测、竞赛要求与近期生态变化，并向AI开发、Agent治理、可信身份、机密计算、金融、制造、汽车与密码迁移扩展。下载目录含论文与标准 PDF、官方 API 文档、官方样例工程、基准/工具快照；news目录单独保存广泛新闻原件和调研表。所有原始来源和失败记录均保留。

整理期间只向本目录写入资料、索引和整理脚本。未修改分析器、现有样例、基线、实验结果；未执行外部仓库代码、安装 HAP 或发起漏洞利用。

## 实验前最重要的结论

1. 先固定威胁模型和标签，再衡量检出率。`Safe` 必须有条件：攻击者能读哪些域、是否掌握 KEK、是否能调用密钥句柄，不能仅由容器类型决定。
2. 官方 HUKS 示例、N-API 示例、CrossFlowBench、JScamd 工具包已获取；它们适合提供独立样例，但需要各自的 SDK/运行环境和标签转换。
3. 现有 B2 已注明“JScamd 风格”。应继续保留“适配基线”的名称；其规则和原论文编号不一致，不能写成原工具复现结果。
4. Node/V8 堆观测与 ArkTS 真机证据分栏。下载的官方示例也不等于已编译、运行或验证安全。
5. 先通过 [05](05-实验方案与启动门槛.md) 中的 P0 门槛，再冻结基准做正式对比；现在可以先做环境和语义校准实验。

正文中的事实链接到原始材料；案例目录中的预期属于根据这些材料制定的实验假设，必须经过独立标注和运行验证。该资料包覆盖本项目当前研究问题，不声称穷尽所有互联网资料，也不预测比赛名次。
