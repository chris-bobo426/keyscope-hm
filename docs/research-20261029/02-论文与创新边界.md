## JScamd 原规则与本地适配的关系

原文 Table 1 的编号如下（摘要转述，细节以原文适用库和条件为准）：

| 原编号 | 原论文主题 |
|---|---|
| C-01 | 不安全密码算法 |
| C-02 | 不安全 DH 组 |
| C-03 | ECB 模式 |
| C-04 | CBC/CFB 的非随机 IV |
| C-05 | 同一密钥下 IV 唯一性 |
| C-06 | PKCS#1 v1.5 填充 |
| C-07 | 可预测密钥 |
| C-08 | KDF 可预测/常量盐 |
| C-09 | KDF 少于1000次迭代 |
| C-10 | 密钥安全长度不足112位 |
| C-11 | 不安全随机数源 |
| C-12 | 不安全 HTTP parser |
| C-13 | 接受无效 TLS 证书 |
| C-14 | 弱 TLS 版本 |
| C-15 | JWT 的 HttpOnly cookie 要求 |
| C-16 | Session cookie 的 HttpOnly 要求 |

项目当前 `models/jscamd_constraints.json` 自述为“JScamd 风格适配”，其中 C12–C16 改成存储、IPC、日志、HUKS导入和清零，C09阈值为10000。这是研究者自定义基线，不能逐编号与原文等同。原文的旧阈值也不是当前生产密码策略推荐值。HKDF 的盐规则应另按 RFC 5869 分析，避免将面向口令派生的假设扩展到所有 KDF。

建议比较分成：B0 简单规则、B1 普通污点、B2 明确公开规则的适配密码误用检查器；原 JScamd 仅在其支持的 JS 语料上另做可选复现。每个方法在共同支持范围上比较，同时公开不支持、失败和超时。

## 值得验证的项目增量（研究假设，尚非已证结论）

| 假设 | 必须提供的证据 | 对应案例 |
|---|---|---|
| 同一秘密的句柄、原始字节、编码副本、包装副本可以区分 | 公开参数/句柄负例、真实材料正例、转换证据链 | K01–K10 |
| 包装是否泄露取决于 KEK 可达性，且编码不应改变包装事实 | 受保护 KEK 与明文共存 KEK 的配对；跨域可读集合及循环依赖测试 | K07–K14 |
| 跨 N-API 保留身份、拷贝/别名和范围 | 外部缓冲区与复制缓冲区、偏移切片、输出参数的源代码级校验 | K18–K26 |
| 多秘密、分支、上下文、字段区分减少误报或漏报 | 独立标签、消融、顺序不变性及不动点收敛检查 | K15–K17、K34–K40 |

“没有检测到”和“不可恢复/安全”不是同义词。项目贡献应落在这些具体判别增益上，并由独立基准和消融实测支持。
