# 工具版本与真实项目候选

## 可复用工具

| 工具 | 已获取 | 使用边界 |
|---|---|---|
| ArkAnalyzer | npm1.0.95归档、registry元数据、官方README、Lab源码快照 | 项目package.json使用`^1.0.95`；正式实验应使用lockfile和实际加载版本。库存在不表示所有插件已注册或参与分析 |
| APAK | 论文；ArkAnalyzer包含相关代码须按实际导出/接口核对 | 需要端到端证明points-to结果进入KeyScope，而非仅实例化类 |
| Clang LibTooling | [官方文档](downloads/docs/clang-libtooling.html)、[编译数据库文档](downloads/docs/clang-compile-commands.html) | 提取真实C/C++声明、别名、注册与参数位置；缺头文件/宏时记录降级，正则摘要与AST摘要分级报告 |
| ArkTaint | [固定提交源码归档](downloads/repos/ArkTaint-ab724f3c.zip)、仓库元数据 | 候选外部分析器；只读归档，未运行、未评估正确率。仓库还包含上传项目副本，不能把它们自动算成独立语料 |
| JScamd | v3 Zenodo归档与元数据、源代码/测试/标签表 | 原工具运行环境与支持库需另验；适合JS复现或作为方法来源 |
| HapRay / ReArk | HapRay论文与仓库提交信息；ReArk最新release元数据 | 相邻生态信息，不是KeyScope当前已接入能力；未安装release程序 |
| DevEco/hdc/hidebug | 官方接口文档、工具页面地址 | 具体设备连接、签名、授权、dump可用性仍须在实验环境验证 |

## 真实项目候选及筛选

| 候选 | 原始来源 | 本地收集程度 | 纳入前要确认 |
|---|---|---|---|
| harmony-utils | [Gitee](https://gitee.com/tongyuyan/harmony-utils) | README | 实际crypto/storage调用、SDK、许可、可构建提交；工具库不等于完整用户应用 |
| ohos_crypto_js | [OpenHarmony SIG](https://gitee.com/openharmony-sig/ohos_crypto_js) | README | 旧crypto-js适配库，页面为关闭状态；与现代CryptoFramework/HUKS分开评估 |
| ohos-openssl | [仓库](https://github.com/ohos-rs/ohos-openssl) | 提交元数据 | OpenSSL构建支持项目，不是完整ArkTS应用；可提供Native构建线索 |
| sportwatch-encrypted-decrypt-filestore | [仓库](https://github.com/Explore-In-HMOS/sportwatch-encrypted-decrypt-filestore) | 提交元数据 | 穿戴/旧平台案例，不能混作新版手机ArkTS应用；先确认调用链和部署条件 |
| 官方Crypto/HUKS样例 | [本地工程](04-案例与基准.md) | 完整所选子树 | 官方示例单列，不混入“独立真实应用数量” |
| JScamd自带语料线索 | [本地工具包](downloads/extracted/JScamd-v3/README.md) | TEST、gDATA、docs等 | 支持语言/库、原始来源、版本、去重、许可及标注来源 |

本次已把以上候选的入口和相关资料保存，未把只含README/元数据的仓库称为“完整项目已下载”。优先使用下载完整、可构建且API范围明确的官方工程和外部基准建立实验；真实应用应在构建/覆盖筛选后另成队列。

纳入表至少记录：是否ArkTS、是否包含C/C++和N-API注册、是否使用密钥相关API、是否可取得源码及固定版本、是否可构建、是否有可重复触发路径、重复来源/派生关系。筛出失败的项目也保留原因，避免只报告成功分析的项目造成偏差。
