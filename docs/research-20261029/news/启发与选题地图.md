# 从行业新闻到可验证的问题

这份地图用于打开研究范围。下面12项是基于公开资料提出的研究假设，不是厂商已经存在漏洞的判断，也不是当前分析器已经实现的能力。新闻编号、发布日期、原始链接和归档文件均可在[完整索引](新闻索引.md)按编号查找。

## 12个方向

| 方向 | 触发资料 | 值得问的问题 | 最小验证与应保留的证据 | 与现有项目的关系 |
|---|---|---|---|---|
| 1. 密钥材料与密钥使用权限分开审计 | N014 华为认证、N056 StrongBox、N070 KMS签名 | 私钥不可导出时，越权主体是否仍能请求签名/解密？ | 自建测试密钥，分别构造“不能读字节但能调用”“不能读也不能调用”；记录主体、授权、调用结果与撤权后结果 | A：直接补充现有密钥风险语义，硬件保障与应用授权分别建模 |
| 2. 用户→智能体→工具的委派身份 | N001 鸿蒙Agent框架、N065 Entra、N068/N069 AWS | 委派链是否丢失用户身份、缩小范围或过期条件？ | 在本地测试服务串联两次委派，改变scope、有效期、audience和撤销状态；记录每跳的授权依据 | B：需要身份与调用链模型，不能把所有token等同于密钥 |
| 3. 跨设备流转后的授权撤销 | N005 鸿蒙互联、N054 会议流转 | 原设备退出、撤回或解绑后，接收端缓存的权限能否继续用？ | 自有设备或模拟协议先测“流转→撤权→重试”；真机与模拟结果分栏，保存状态迁移 | A/B：复用密钥身份和生命周期思路，需真实流转样例 |
| 4. TEE支撑的分布式数字身份 | N007 DID课件目录、N052 鸿蒙智能白皮书 | 可信执行环境之外的调用方、会话和恢复流程如何绑定？ | 先取得并读完DID课件再确定接口；当前只画威胁模型，不从标题臆测协议。后续验证错误主体、重放和恢复身份绑定 | B：有明确宣讲入口，尚不能称已复现方案 |
| 5. AI生成鸿蒙密码代码的正确性 | N015/N021 华为AI开发、N084 Codebuddy Security | AI会不会把算法用对，却把密钥转换、日志或生命周期写错？ | 冻结一组真实需求、模型/提示/采样参数；人工独立标注，比较原始生成、工具修复和人工修复，报告代价及失败例 | A：可成为现有分析器的独立应用场景，不能边生成边挑样本 |
| 6. SDK包装隐藏的密钥表示变化 | N012 UKey SDK线索、N056 硬件密钥，加原资料包的跨语言研究 | JS/ArkTS到Native再到厂商SDK后，材料、别名与句柄是否被混淆？ | 官方样例加独立改写：字节→Base64→Native拷贝→日志，另设“仅句柄”反例；保留跨层真值 | A：贴合当前主线；SDK月刊全文仍待取得 |
| 7. 数字资产继承与恢复边界 | N044 华为数字资产继承、N080/N081 Passkey | 恢复、继承、撤销能否避免“恢复凭据变成长期万能凭据”？ | 先按官方说明列角色、激活条件和可访问对象；自建等价状态机测试过期、重复使用、撤销、范围越界 | B：新业务场景，不能对真实他人资产测试 |
| 8. 跨设备加密状态的唯一性 | N005 跨端能力，加NIST GCM要求 | 设备复制、备份恢复、并发和重试是否使同一密钥下nonce重复？ | 在自建程序复制计数器状态并并发加密；记录key identity、nonce、设备/会话和恢复事件。用随机与持久计数器作条件化对照 | A：从单函数检查扩展到生命周期；这是推导的风险，不是新闻披露漏洞 |
| 9. Agent记忆与KV Cache中的秘密残留 | N017 INSPIRE提及Agentic记忆、机密计算 | 一次输入的秘密在摘要、记忆、缓存、工具日志中衍生出多少副本？ | 仅用合成标记，固定模型与运行环境；跟踪原文及编码变体，区分可读副本、不可逆摘要、授权持久化；删除后再采样 | B：当前Node堆观测不能直接证明推理框架/鸿蒙运行时行为 |
| 10. 后量子迁移中的密码资产清单 | N031 量子安全网络、N057 Android、N079 NIST | 一个密钥或证书有哪些算法、协议、SDK和更新依赖？ | 先静态识别算法/密钥用途/调用位置，人工核对版本和依赖；产出迁移影响图，不自行设计新算法 | B/C：适合拓展价值论证，范围大，不宜抢占主实验 |
| 11. 工业设备的投运、维修和退役 | N035 鸿企100、N040 OpenHarmony设备 | 换件、返修和重新投运后，旧设备身份或凭据是否继续有效？ | 从公开行业流程建立测试状态机；自有样机或仿真记录初始化、换件、注销、重新注册。硬件结论必须来自硬件 | B：更具体的落地场景，先找到可获得设备和样例 |
| 12. 安全告警的证据与误报成本 | N013/N053 应用治理、N076 GitHub检测、N084 审计产品 | 哪些告警能给出可复核的泄露路径与恢复条件？ | 构建相同字符串分别为真实密钥、公钥、别名、测试占位符、包裹密文的盲测组；统计误报、漏报、定位和人工复核时间 | A：直接帮助比赛实验可信度，不只展示一个总检出率 |

## 建议先深挖的三个方向

1. **密钥材料泄露与使用权限越界。** 这能解释硬件保护存在时应用层审计仍有什么价值；先用本地受控例子明确语义，再决定是否做真实HUKS调用。
2. **AI生成鸿蒙代码的密码安全。** 新闻提供应用场景，独立需求集和标注提供实验证据；必须控制模型、提示和选择偏差。
3. **跨语言表示、复制与生命周期。** 保留现有技术主线，把跨设备、SDK与恢复情景作为新的样本来源，先证明分析增益。

后量子、汽车和工业物联可作为未来方向与行业背景。是否纳入这次参赛，应由样例可获得性、最小实验成本和能否形成独立证据决定，不能按新闻热度直接堆功能。

## 把一条新闻变成实验的记录模板

| 字段 | 需要写清楚的内容 |
|---|---|
| 来源事实 | 原文真正宣布的功能、时间、版本与适用范围 |
| 尚未回答的问题 | 原文没有给出、需要自己测量的部分 |
| 受保护对象 | 原始密钥、包装密文、别名、句柄、token、证书还是权限 |
| 主体与前提 | 谁能读取、调用或委派；是否掌握KEK；在哪个设备/安全域 |
| 最小正反例 | 只改变一个关键条件，包含预期安全与预期有风险的情况 |
| 观测 | 可核对日志、调用结果、内存证据或权限决定；每种证据有环境标签 |
| 对照 | 现有规则、通用工具、人工判断或去掉关键分析能力的消融 |
| 停止条件 | 样例不可取得、只能模拟、无法独立标注时，降低结论范围 |

执行步骤和空白模板见[实验方案](../05-实验方案与启动门槛.md)、[40个验证场景](../examples/cases.md)。本次仅整理资料，没有启动以上新实验。
