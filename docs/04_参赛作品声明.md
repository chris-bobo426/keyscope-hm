# 第五届“华秦杯”网络安全创新大赛创意作品赛 — 参赛作品声明

## 1. 参赛作品原创性与自主知识产权声明

本团队郑重声明：参赛作品 **《鸿钥卫士（KeyScope-HM）——面向 HarmonyOS 混合应用的跨运行时密钥表示与暴露风险分析系统》** 系本团队独立构思、自主设计与研发完成的原创性技术成果。

1. **核心理论与算法完全自研**：
   - **逻辑秘密与物理表示解耦形式化模型（LSR）**（[`core-ts/repr.ts`](../core-ts/repr.ts)）；
   - **跨运行时表示传播与 1-Call-Site 堆克隆算法（RepFlow）**（[`core-ts/analysis/repflow.ts`](../core-ts/analysis/repflow.ts)、[`core-ts/rules/transfer.ts`](../core-ts/rules/transfer.ts)）；
   - **秘密可恢复性最小不动点 $\mathrm{Rec}(\kappa, D)$ 递归求解器与策略判定器**（[`core-ts/rec.ts`](../core-ts/rec.ts)）；
   - **Native C/C++ NAPI 拷贝/别名（Copy vs. Alias）与必达清零表示摘要器**（[`core-ts/bridge/napi_bridge.ts`](../core-ts/bridge/napi_bridge.ts)、[`native-py/napi_summarizer.py`](../native-py/napi_summarizer.py)）；
   - **指向纯度驱动的三级置信度分级器与多模态报告生成器**（[`core-ts/grade.ts`](../core-ts/grade.ts)、[`report/report_generator.ts`](../report/report_generator.ts)）。
2. **评测基准与动态验证套件完全自建**：
   - **64 个配对鸿蒙混合应用基准 `HarmonyKeyRepBench`**（[`bench/generate_benchmark.ts`](../bench/generate_benchmark.ts)）；
   - **编译器 `-O0` vs `-O2` 死存储消除（DSE）二进制反汇编实验与 V8 托管堆快照取证实验**（[`dynamic/run_dynamic_experiments.ts`](../dynamic/run_dynamic_experiments.ts)）。

本作品不存在任何侵犯第三方知识产权、商业秘密或学术不端行为。

## 3. 数据脱敏、非涉密与负责任安全研究声明

1. **非涉密声明**：本作品全部代码、模型规则、合成基准样本及文档均在公开技术资料与开源生态基础上完成，**不涉及任何国家秘密、国防秘密或未公开商业机密**。
2. **测试对象合规性**：本作品在真实项目评估阶段所扫描的 8 个仓库（`harmonyos_samples/cipher`、`harmonyos_samples/crypto-collection`、`harmonyos_samples/preferences`、`openharmony-sig/ohos_crypto_js`、`openharmony-tpc/ohos_coap`、`openharmony-sig/ohos_mqtt`、`openharmony/security_crypto_framework`、`openharmony/security_huks`）均为 Gitee 平台公开发布的 Apache-2.0 / MulanPSL-2.0 开源仓库，仅在本地离线克隆状态下进行静态代码审计，未对任何在线生产服务或第三方服务器发起网络探测或攻击。
3. **负责任披露原则**：针对在开源仓库中发现的 Native 缓冲区漏清零、静态 GCM Nonce 与密钥字符串驻留问题，本团队已在《03_其他文档_基准说明与复现手册》中整理了标准修复补丁方案，严格遵循负责任漏洞披露（Responsible Disclosure）规范，仅用于提升开源鸿蒙生态密码安全性。
