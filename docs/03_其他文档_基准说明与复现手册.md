## 1. 工程目录结构与核心模块索引

## 2. 一键复现操作指南（Step-by-Step Reproduction）

### 2.1 环境依赖检查

在仓库根目录下打开终端（PowerShell 或 Bash），确认已安装 Node.js（推荐 `v22+` 或 `v24+`，内置 `node:sqlite`）并已安装项目依赖：

```powershell
node -v
npm install
```

### 2.2 一键运行 G1–G5 全量验收关口测试、交互式编译器工作台与 TypeScript 类型检查

```powershell
# 一键运行全流程验收脚本（含严格 $LASTEXITCODE 失败即停止检查）
powershell -ExecutionPolicy Bypass -File .\run_all.ps1

# 或运行五道验收关口 (G1-G5) 与编译检查
npm test
npm run build

# 启动交互式编译器三地址 IR / libclang AST / SVG 溯源图 Web 分析工作台 (http://localhost:3000)
npm run ui
```

- **预期输出**：依次通过 `[Gate G1]`（ArkAnalyzer Scene/CFG/3-Address IR + APAK PAG + LSR 不动点）、`[Gate G2]`（Native C/C++ NAPI Copy vs Alias 摘要 + `libclang.dll 15.0.4` 真实 AST 节点提取）、`[Gate G3]`（64 样本 × 9 方法基准评测，Full v3 F1=100.00%, A-FPR=0.00%）、`[Gate G4]`（`-O0` vs `-O2` DSE 反汇编、Win32 `ReadProcessMemory` 四组内存取证含未清零 Buffer 正控 10/10、8 个真实仓库 SQLite 审计库含 `source_snippet` 证据与多模态报告）、`[Gate G5]`（5 大独立审查反例 `wrapped_encoded` / `merge_order` / `native_derive_output` / `file_name_dependency` / `pos_control_heap` 与外部留出泛化测试），最终打印 `ALL 5 GATES (G1, G2, G3, G4, G5) PASSED SUCCESSFULLY!`。

### 2.3 重新生成并评测 64 个配对基准样本 (`HarmonyKeyRepBench`)

```powershell
npx tsx bench/generate_benchmark.ts
npx tsx eval/run_benchmark_eval.ts
```

- **输出文件**：[`bench/benchmark_manifest.json`](../bench/benchmark_manifest.json) 与 [`eval/benchmark_results.json`](../eval/benchmark_results.json)。

### 2.4 重新运行编译器 DSE 二进制反汇编与 V8 托管堆快照实验

```powershell
npx tsx dynamic/run_dynamic_experiments.ts
```

- **输出文件**：[`dynamic/disasm_experiment/disasm_results.json`](../dynamic/disasm_experiment/disasm_results.json) 与 [`dynamic/heap_experiment/heap_results.json`](../dynamic/heap_experiment/heap_results.json)。

### 2.5 重新运行 8 个真实开源鸿蒙仓库扫描与双人一致性评估

```powershell
npx tsx realworld/run_realworld_scan.ts
```

- **输出文件**：[`realworld/keyscope_realworld.db`](../realworld/keyscope_realworld.db) 与 [`realworld/realworld_summary.json`](../realworld/realworld_summary.json)。

### 2.6 使用 CLI 扫描任意鸿蒙工程并生成 HTML / SARIF / CBOM 报告

```powershell
# 扫描单个基准工程
npx tsx core-ts/cli.ts bench/samples/F3_v1_direct_B_Risky --output-dir report/output

# 扫描全部 8 个真实开源鸿蒙仓库并生成综合报告
npx tsx core-ts/cli.ts --all-realworld --output-dir report/output
```

- **输出文件**：
  - 交互式 HTML 溯源图报告：[`report/output/keyscope_report.html`](../report/output/keyscope_report.html)
  - OASIS SARIF 2.1.0 报告：[`report/output/keyscope_results.sarif.json`](../report/output/keyscope_results.sarif.json)
  - OWASP CycloneDX 1.6 CBOM 报告：[`report/output/keyscope_cbom.cdx.json`](../report/output/keyscope_cbom.cdx.json)

## 3. 真实开源仓库负责任披露与修复建议记录

针对本系统在 OpenHarmony 与 HarmonyOS 真实开源仓库中发现的跨层未清零与表示暴露问题，我们制定了配套的标准修复补丁建议：

| 仓库名称 | 缺陷文件与行号 | 违规规则 | 标准修复方案（Patch 概要） |
| :--- | :--- | :---: | :--- |
| `openharmony/security_crypto_framework` | `frameworks/js/napi/crypto/src/napi_key_agreement.cpp:83-87` | `E1_M4` | 在 `FreeKeyAgreementCtx` 中将 `HcfFree(ctx->returnSecret.data)` 替换为 `HcfBlobDataClearAndFree(&ctx->returnSecret)`，与同步接口 `JsGenerateSecretSync` 保持一致。 |
| `openharmony/security_huks` | `interfaces/kits/napi/src/v8/huks_napi_common.cpp:158-174` & `v9/huks_napi_common_item.cpp:231-243` | `E1_M4` | 在 `FreeParsedParams` 释放 `HKS_TAG_TYPE_BYTES` 类型的 `params[i].blob.data` 前，先调用 `(void)memset_s(params[i].blob.data, params[i].blob.size, 0, params[i].blob.size)`。 |
| `openharmony-sig/ohos_mqtt` | `ohos_Mqtt/src/main/cpp/mqtt_napi/connect_context.cpp:235-243` & `mqtt_impl.cpp:539-554` | `V1`, `E1_M4` | 在 `FreeConnectcontext` 中对 `connectOptions.password` 与 `sslOptions.privateKeyPassword` 执行 `memset_s` 清零后再 `delete[]`，修复残留与内存泄漏。 |
